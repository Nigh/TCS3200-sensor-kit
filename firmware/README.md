# 固件

固件运行于 Waveshare RP2040-Zero（RP2040，2 MB Flash），使用 Pico SDK 2.3.0 和 TinyUSB。核心 1 按时间槽采集 TCS3200 输出，核心 0 处理 USB CDC 传输和键鼠触发状态机。传感器模块的照明 LED 保持关闭。

硬件设计见 [PCB 工程](../layout/README.md) 和 [外壳设计](../3D/README.md)；采样界面与操作步骤见 [上位机说明](../host/README.md)。

## 接线

以下为 GPIO 编号，实际板上位置请按板卡丝印/引脚图核对。

| TCS3200 | RP2040-Zero |
|---|---|
| OUT | GP2 |
| S2 | GP1 |
| S3 | GP0 |
| S0 | GP10 |
| S1 | GP11 |
| OE（若模块引出） | GP12，固件拉低；未引出时确认模块已使能 |
| GND | GND |
| 传感器 VCC | 优先 3V3，确认模块支持该供电 |
| 照明 LED 供电/使能 | 不连接/关闭；按具体模块电路处理 |

传感器芯片必须供电，LED 与 VCC 未必在模块上独立。若模块需要 5 V，OUT 必须经过合适的电平转换到 3.3 V，不能直接接入 RP2040 GPIO。屏幕前固定距离和角度，并遮挡环境光。板载 GP16 RGB LED 不使用。

修改接线时同步更新 `src/sensor.h` 和本表。100% 输出比例由固件设置 S0/S1 为高；不要另外短接冲突电平。

## 编译、刷写与自检

在仓库根目录运行 `make`，或本目录运行 `make`。Docker 镜像固定为 `xianii/pico-sdk:2.3.0`；使用本地 SDK 时设置 `PICO_SDK_PATH` 并运行 `make build`，需要 ARM GCC、CMake 和 Ninja。

生成 `build/src/tcs3200_sensor.uf2`、`.elf`、`.bin`。按住 BOOT 接入 USB，复制 UF2 到引导盘。也可在测量模式通过协议 BOOTSEL 命令进入引导盘。

`make test` 在主机编译协议和触发逻辑并启用 ASan/UBSan，验证拆包、CRC、异常长度、超时、参数校验、确认/迟滞、取消与释放、计时回绕和频率转换；USB 桩测试验证命令响应、部分写入、背压丢帧、DTR 关闭释放与挂起取消。Python 小型指令模拟执行实际 PIO 源码，验证周期计数、相位、占空比及无边沿预算，并独立校验协议文档的十六进制示例。它不模拟真实 GPIO 电气特性或完整 USB 硬件。

## GP28 LED 阶跃响应诊断

### 编译与环境

在仓库根目录运行 `make`，使用 Docker 镜像 `xianii/pico-sdk:2.3.0` 编译。输出诊断固件 `firmware/build/src/tcs3200_step_response.uf2`，同时生成正常固件。也可配置 Pico SDK 2.3.0、ARM GCC、CMake 和 Ninja，设置 `PICO_SDK_PATH` 后运行 `make build`。

断电接线：白色 LED 阳极经限流电阻接 3V3，阴极接 GP28；没有电阻时先串入电阻（可先用 330 Ω，实测电流和亮度）。GP28 低电平点亮、高电平熄灭。OUT 接 GP2，电平不得超过 3.3 V。关闭模块照明 LED，固定 LED 和传感器距离并遮住环境光。诊断固件固定 Clear 通道和 100% 输出比例。

按住 BOOT 接入 USB，将诊断 UF2 复制到引导盘。诊断固件仅提供 CDC，不支持正常固件的协议或 HID。完成后刷回 `firmware/build/src/tcs3200_sensor.uf2`。

### 采集与分析

Linux 主机需要 Python 3 标准库和串口访问权限。关闭正常上位机，在仓库根目录按实际端口运行：

```sh
python3 firmware/tools/step_response.py capture --port /dev/ttyACM0 --out step-response-run --repeats 10
python3 firmware/tools/step_response.py analyze --data step-response-run --periods
python3 -m unittest discover -s firmware/tests -p test_step_response.py
```

采集拒绝覆盖已有目录，先保存亮暗平台和试跑，再冻结阈值、各方向档位、观察时长及共用斜率窗口。可用 `--slope-window-ms` 指定 5～500 ms 整数窗口。原始帧分别保存于 `pilot/` 和 `traces/`；`settings.json` 保存冻结参数。中断后可离线分析已保存的完整正式帧。预检失败时，`analyze --periods` 仍可导出预检周期。`summary.csv` 的空字段表示缺测，`periods.csv` 包含每个完整周期；跨阶跃周期保留，频率在周期右边沿才可用。

以逻辑分析仪（至少 25 MS/s）同时观察 GP28 和 GP2，核对阶跃极性、上沿周期和阈值时间，允许一个采样间隔加仪器分辨率。用不透光挡片遮住光路、保留电气接线，另用新目录和 `--repeats 1` 验证预检因光阶跃不足停止；若仍出现同步大阶跃，检查电源纹波和串扰。

时间零点是 GP28 电气阶跃，不是 LED 光通量阶跃。LED 荧光粉、输出相位和完整周期估计都会影响结果；fast 的 0.2 μs 和 long 的 4 μs 是采样间隔，不是光学延迟精度。[TCS3200 数据手册](https://look.ams-osram.com/m/664723bdb31f55db/original/TCS3200-DS000107.pdf) 给出的辐照阶跃响应约为新频率的一个周期加 1 μs，仅供对照。分离 LED 光学延迟需要快速光电二极管与 GP28、OUT 共用示波器时基。

### 测量方法与结果

PIO 在同一时基记录 GP28 电气阶跃和 GP2 上升沿，固定 Clear 和 100% 输出比例。上升为 LED 点亮，下降为 LED 熄灭。每组先采预检帧，冻结亮暗平台、分析窗口和档位，再交替采集上升、下降各 10 次。亮暗平台使用远离阶跃的完整周期频率中位数，MAD 是未缩放的绝对偏差中位数。

每两个相邻上升沿计算一个周期和频率，时间标记为周期右边沿。以亮暗平台频率差计算进度，`t10` 和 `t90` 分别是阶跃后首次达到 10% 和 90% 的频率点；二者落在同一点时，过渡时间记为缺测。峰值速率是 6 ms 窗口内的最大平均频率变化率；P95 使用最近秩。

三组实测逐步提高暗平台亮度，均使用 fast 档、0.2 μs 采样间隔，每方向 10 次。每组亮暗频率、MAD、观察时长和窗口如下：

## 固件行为

- RGB+C 四通道独立开关，启用通道使用相同的自适应时间槽，非空采集最大计划组频率为 6～4000 Hz；PIO 内部 32 位计数，USB 每通道 32 位，单位 1 Hz，默认低频阈值 15 kHz。阈值可通过 SET_LOW 或 SET_CONFIG 设置，合法范围 100～600000 Hz。时间槽为 `max(250, ceil(4000000/low_hz)+40)` μs，组间隔为启用通道数乘时间槽；全关时每 10 ms 发送空状态帧；默认 15 kHz 对应 307 μs / 1228 μs / 814 Hz，4 kHz 对应 1040 μs / 4160 μs / 240 Hz。
- PIO 丢弃切换后的一个完整周期，再测完整周期；默认 125 MHz 时计数粒度约 24 ns，不能理解成传感器有 24 ns 光学响应。
- 每通道最多采集至时间槽结束前 10 μs；低频、无信号或超时值为零，附带 LOW。所选通道中 LOW 的零值正常参与比较，clip/LATE 则暂停连续确认。
- HID interrupt IN 描述符请求 1 ms（1000 Hz）；GET_USB_STATUS 返回该请求和基于 EP1 IN NAK 的 1 秒空闲轮询估算。观测中断 ≥1 ms 或发送报告时丢弃窗口；不启用 NAK IRQ、不发送探测报告，估算不等同于总线分析仪测量。
- CDC 仅传二进制帧；打开端口后需要 DTR=1，两种模式均发送数据。配置由上位机根据实测填写，RAM 保存，不自动进入测试模式。
- 触发逻辑比较所选通道与 reference[0] 的原始频率差，含进入/退出迟滞及持续确认；一个键位和修饰键组合，或鼠标按钮组合，延迟后按下，再按配置时间释放；单次测试（mode=1）只执行一次并回到测量模式；连续测试（mode=2）释放后重新等待 ARM 色，直到手动停止，释放前排队的样本不能重新 ARM。
- 断连、关闭 CDC、挂起、切换到测量模式会停止新动作；已提交的按下安排释放。协议细节及主机交互顺序统一见 [协议文档](../docs/protocol.md)。

协议已升级为 v4，须同时升级上位机；v1/v2/v3 固件/上位机不再配对。测试状态机按所配置阈值对应的组间隔检查连续性，确认时长仍使用真实设备微秒时间。

## 上板验证

刷写后按以下步骤检查接线、采样时序与触发行为：

1. CDC 和键鼠均正常枚举，DTR 后得到 CRC 正确的 40 字节采样帧。
2. 逻辑分析仪确认 S2/S3 为 R→G→B→Clear，分别设置 4/15/20 kHz，确认 1040/307/250 μs 时间槽、4160/1228/1000 μs 组周期；同时观察实际 OUT 频率与 LOW/LATE 比例。
3. 各屏幕颜色、亮度下测量最弱通道和 PWM 波动，核对频率与外部仪器，确定 low_hz 和 ARM 容差。
4. 根据实测配置测试模式，在文本输入框或测试程序验证按下/释放；确认取消、关闭 CDC、USB 挂起及重连时没有重复动作或卡键。
5. 持续接收并停止读取，检查序号、capture_drops、stream_drops，确认传输背压不改变采集时序。

LOW 无法区分黑屏、无光与 OUT 断线，可能触发偏离；最终按键延迟还受 USB 与系统调度影响。校验完成后再把固件用于需要准确动作时序的场景。
