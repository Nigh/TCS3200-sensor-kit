# Linux 上位机

MyGo 原生 Go UI，展示 TCS3200 的 R/G/B/Clear 四通道脉宽；使用 [USB 协议 v3](../docs/protocol.md)。不使用浏览器前端。提供波形测量和独立自动触发测试 Tab；不提供 BOOTSEL、导出或超过 10 秒的历史。

## 运行与构建

需要 Go **1.27.1+**（`GOTOOLCHAIN=auto` 可自动下载），以及可用的 Linux 图形桌面。原生界面需要 GTK 3 与 OpenGL 驱动；无需 WebKitGTK 或 Node/Bun。Ubuntu/Debian 可安装 `libgtk-3-0`、`libgl1`、`fonts-noto-cjk`；其他发行版安装对应运行库。工具链和 Go 依赖仅首次构建时需要联网。

在仓库根目录运行：

```sh
make host          # 启动实际设备界面
make host-demo     # 合成 1 kHz 信号，明确标注，禁用 USB 连接；无需硬件
make host-build    # 发布构建：host/build/tcs3200-host（CGO_ENABLED=0）
make host-test     # Go 测试与 vet
```

也可在本目录运行 `go run .`、`go run . --demo`。现有根目录 `make`、`make test` 仍用于固件。

顶部两个 Tab 等宽，采用有边框的整条页签栏，选中项使用粉色填充；保留左右键、Home/End 切换。窗口默认 1280×900，最小 1080×760。使用 Noto Sans CJK SC 和框架字体回退。Wayland 与 X11 由 GTK 选择；若特定驱动下 Wayland 异常，可用 `GDK_BACKEND=x11 ./host/build/tcs3200-host` 在 XWayland 中运行。

## 设备连接

1. 点击“枚举设备”，只列出 VID `ACDC` / PID `4015` 的 USB CDC 端口，以端口路径和序列号区分多块板。
2. 选择设备并点击“连接”。应用打开二进制 CDC、置 DTR，持续读取，同时通过 GET_STATUS 检查协议 v3 布局及阈值对应的 0～4000 Hz / 250～1040 μs 采样参数。波特率设置为 115200，不限制 USB bulk 传输速度。
3. 状态显示“已连接”后观察四通道波形。意外拔出、接收错误或连续 2 秒没有有效采样时停止连接并保留最后波形，显示错误原因。重新插入后手动枚举、选择、连接；不会自动重连。
4. “断开”关闭 CDC 并取消未完成命令。新连接清空旧解码、时间轴、原始数据和快照。

**权限错误：**确认端口存在且未被串口终端占用，检查 `ls -l /dev/ttyACM*` 的属组。按发行版规则将用户加入相应串口组（Ubuntu 通常为 `dialout`），重新登录后再启动。不要使用 root 启动 GUI，也不需要修改设备为所有人可写。枚举失败会显示错误，空列表会提示检查 USB。

## HID 轮询

状态区显示固件请求的 **1000 Hz（1 ms）**，以及 MCU 观测的 **空闲轮询估算 Hz**。后者来自 RP2040 HID IN 端点 NAK 标志，统计连续 1 秒的空闲窗口；点击发送中、挂起、断开或观测循环有 ≥1 ms 缺口时显示“暂不可测”，旧固件未提供扩展查询时显示“—”。不发送额外鼠标报告，不把采样率、USB 帧频或点击次数作为轮询速率。实际轮询由主机安排，严格时序仍需 USB 分析仪验证。

## 图表和统计

- 四图共享 X 轴；默认最近 10 秒，Y 轴分别自动取整。所有采样读数为 **μs**，保留 1 位小数：按 50% 占空比换算单个高/低电平脉宽，`脉宽 = 500000 / 频率Hz = 50000 / 协议原始值`，不是完整周期。
- 使用设备采样时间而非 USB 到达时间绘图；展开 32 位时间戳回绕。序号缺失或时间不连续的位置断开折线，保留 LOW/CLIP/LATE 标志。LOW 零值与 CLIP 饱和值没有可换算的精确脉宽，显示“— μs”、波形断开，不参与脉宽统计。
- 滚轮以指针位置缩放 X 轴，范围 **10 ms–10 s**；开始缩放或拖动即固定快照。拖动在快照内平移；图表取得键盘焦点后，`=` / `+`、`-` 缩放，左右方向键平移。
- “暂停刷新”冻结当前最多 10 秒的原始样本，USB 继续接收并独立更新最近 10 秒缓冲。“恢复实时”“回到实时”或 Esc 放弃旧快照，显示最新 10 秒。长时间暂停不会累计无限历史。
- 密集波形悬停显示当前物理像素时间桶的区间、样本数、Max、Min、中位数，并联动四图时间游标。统计来自原始样本，和绘制降采样分离；偶数样本的中位数取中间两数平均。空桶显示无数据。时间区间以当前视口右端为 0；最后一个桶包含右端样本。
- 放大到当前通道每个物理像素列最多一个样本时，停止时间桶聚合，直接绘制原始折线与空心采样圆点；鼠标距圆点中心 6 DIP 内时填实该点。悬停读数改为最近样本的脉宽和时间，时间以视口右端为零，精确显示到 0.1 ms；游标吸附到实际样本时间。缩小后自动恢复聚合与 Max/Min/中位数。
- 底部显示主机按序号计算的丢组、设备采集/发送丢组和两端协议错误。设备计数从启动累计，主机计数从连接会话开始；暂停不停止采集或命令处理。图表采集刷新请求最多 30 Hz，鼠标和键盘交互可额外触发即时帧。

## 低频阈值

输入低频阈值，合法范围 **4000–600000 Hz**。离开输入框或点击“应用”时自动限幅：过低取 4000，过高取 600000，小数四舍五入到整数 Hz；空值或非法文本恢复设备当前阈值（未连接时为默认 15000 Hz）。编辑过程中允许暂存未完成文本。标题栏同时显示设备已应用阈值对应的最大采样率和所填阈值的预览采样率，后者不代表已发送到设备。仅测量模式且设备处于 WAIT 时可提交。成功后等待 ACK、GET_STATUS 回读一致，再清空旧图表和快照；按设备时钟丢弃直到状态快照之后 100 ms 的样本，避免把排队旧采样混入新阈值图表。

阈值设置会按固件约定使已有测试配置失效，配置只存于设备 RAM。设备拒绝命令时保留连接并显示结果；通信超时后不自动重发，而是断开并提示重新连接确认。命令严格串行，默认响应超时 1 秒。

固件根据阈值自动分配采集时间：`slot_us = max(250, ceil(4000000/low_hz)+40)`，N 个启用通道的组周期为 `N*slot_us`，最大计划采样率为 `floor(1000000/(N*slot_us))` Hz。四通道 4/5/10/15/20 kHz 阈值分别对应最大 240/297/568/814/1000 Hz。这里显示的是当前采集策略的计划上限，实际收到的速率可能因丢组或 USB 背压更低。图表按设备时间戳绘制，正常降速不会被当作丢组。

**配套升级：**固件与上位机均使用 v3，必须同时升级。默认仍开启全部四通道、15 kHz 低频阈值，最大组频率 814 Hz。

## 通道与自动触发测试

两个 Tab 共用通道开关和低频阈值；全部关闭时不采集传感器，保留状态空帧。20 kHz 及以上单通道最高 4000 Hz，四通道最高 1000 Hz。少开通道后也可降低低频阈值，在相近速率下扩大动态范围。

1. 打开“自动触发测试”，只开启一个通道（R/G/B/Clear 均可）。页面显示最近 500 ms 的平均值、最大值、最小值、峰峰值和有效样本数，不显示波形。统计先逐样本换算脉宽，再计算平均值及极值；LOW 零值、关闭、CLIP 和 LATE 样本不参与。
2. 对准 ARM 颜色，点击 **Set ARM Color** 按最近 500 ms 有效样本的平均值保存基准，并依据最大最小值自动填写容差和偏离阈值（留有噪声余量与迟滞间隔，可手动微调）；变更通道、低频阈值或重新连接后需要重新保存。
   固件协议仍用频率距离：上位机将脉宽容差按较短脉宽边界换算为频率距离，较长脉宽侧边界因此不对称，且受 10 Hz 量化影响。低频阈值设置属于设备采集参数，继续使用 Hz；采样率及 HID 轮询率也继续使用 Hz。
3. 设置 ARM 容差、偏离阈值（单位均为 μs，偏离阈值必须更大且小于基准脉宽）与 **0～1000 ms** 整数 Delay。
4. 点击 **Test**：检测到 ARM 颜色后进入 Armed，达到偏离阈值后由 MCU 计时，延时到期发送一次左键按下及释放。再次点击 **取消 Test** 可取消未发送动作；已发送的按下仍会释放。
5. 每次 Test 只执行一次，完成后回到测量模式；点击 **连续测试** 则每次释放后重新等待 ARM 颜色，偏离后再次点击，直到点击 **停止连续测试**。测试期间锁定配置；断开、挂起取消测试，不自动重新开始。

判断及延时均在 MCU 上执行，上位机只配置与显示。USB HID 的 1 ms 轮询、背压和操作系统调度仍会影响最终收到点击的时间；需上板实测校准。LOW 无法区分黑屏和传感器断线。

## 临时性能优化与后续迁移

参考 [mygo PR #363](https://github.com/egoist/mygo/pull/363)，当前只在应用侧按**物理像素列**取 Min/Max，按原始时间顺序保留极值、连续段端点与缺口；复用输出缓冲，正常连续波形绘制点数约为每像素两个点。原始采样数据（最高 4000 Hz）仍保留，未做平滑或平均。

依赖固定到上游 `7769928c78b7`（完整版本见 go.mod），没有使用相邻 mygo checkout、replace 或未合并 fork。临时代码在 `data.go`，带 `shortcut:` 注释。目前仍使用 `chart.Line` / `StrokePath` CPU 路径，不能承诺 PR GPU 路径的性能。

PR 合并并发布后：

1. 显式升级并固定包含 PR 的上游版本，核对公开 API。
2. 用 `chart.MinMax` 替换本地 `minmax`，用 `Painter.StrokePolyline` 替换当前 `chart.Line` / `StrokePath` 调用，复用折线点缓冲。
3. 删除临时降采样实现及其专用测试；保留原始样本、hover、缺口和生命周期测试。
4. 重跑 Linux 1×/2× 渲染、交互、CPU/内存与持续运行检查。仅升级依赖不会自动切换到 PR 的 opt-in GPU API。

主题参考 [Nigh/xianii-theme](https://github.com/Nigh/xianii-theme)（MIT）；在 `ui.Theme` 中映射其中性深色、粉色强调与 8 DIP 圆角，没有引入 CSS/Svelte 依赖。

## 验证

```sh
cd host
go test -race ./...
go vet ./...
CGO_ENABLED=0 go build -tags mygo_noinspector ./...
go test -run '^$' -bench BenchmarkMinMax -benchmem
TCS3200_SCREENSHOTS=build/screens go test -run 'TestMeasurementUI|TestEmptyUI'
```

测试覆盖协议校验向量、任意拆包/粘包、坏 CRC 和截断恢复、时间与序号回绕、三分钟等量合成采样的有界保留、丢组、Min/Max 尖峰和缺口、统计、CDC 打开失败/取消/拒绝/超时/关闭/重连，动态速率和边界、阈值自动限幅与速率预览，以及原生界面的 hover、暂停、缩放、平移和恢复。截图检查使用框架原生 headless 渲染；另在当前 Linux 桌面启动过实际窗口。

这些测试不代替 USB 实机验收。需接入板卡确认：多设备选择、DTR 启流、连续采集、阈值变化、忙状态、实际拔插与恢复、真实 LOW/CLIP/LATE、长时间运行及 1×/2× GPU 表现。合成采样的时间跨度测试不是三分钟硬件稳定性测试。
